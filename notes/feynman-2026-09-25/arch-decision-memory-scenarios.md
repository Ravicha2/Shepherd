## Executive summary

1. **The strongest evidence base beyond compliance checking is the architecture↔defects line.** Design-rule-space / architecture-anti-pattern research shows that error- and change-prone files are architecturally connected and that current architectural decay predicts future issue- and change-proneness (Xiao et al., ICSE 2014 [1]; Xiao et al., ICSE 2016 [97]; Cai et al., TSE 2019 [2]; Mo et al., TSE 2019 [3]; Le et al., ICSA 2021 [4]). This is *not* something flat code RAG or per-file static analysis sees; it is exactly the kind of transitive, structure-level knowledge Shepherd's constraint-path traversal computes.
2. **But the causal chain is unproven:** all of this evidence is correlational or predictive, mostly Java, and no published study demonstrates that conformance checking reduces future defect rates in a controlled experiment — an explicitly documented gap in the verified literature; the closest causal-flavored evidence is the practitioner-verified ICSE-SEIP 2015 case and the single-repo longitudinal paydown study (Kazman et al. 2015 [5]; Nayebi et al. 2019 [6]; research notes T2 §Correlation-vs-causation [96]). A Python bug-fixing case study with proper attribution is therefore both novel and needed.
3. **The bug-fixing scenario has no published incumbent.** A 2025 systematic literature review of LLM×software-architecture (search through March 2025) found *no* LLM work on architecture conformance checking and only one work generating code for architectural components (Schmid et al., arXiv 2505.16697 [7]); an LLM multi-model pipeline for detecting ADR decision violations exists as a single 2026 study, weak on implicit/deployment decisions (Su et al., arXiv 2602.07609 [8]). This is an open lane.
4. **Python benchmark coverage is good for bug tasks and code review, absent for ADR/decision violations.** SWE-bench (2,294 test) [9], SWE-bench Verified (500) [10], SWE-bench Lite (300) [11], SWE-Gym (2,438) [12], SWE-smith (59,136 train) [13], BugsInPy (493 bugs/17 repos) [14], MULocBench (1,100 issues/46 Python repos) [15], LocBench (560/163) [16], SWR-Bench (1,000 PRs) [17], SWE-CARE (601/70) [18], PyMigBench (3,096 changes) [19] are all Python. No released, code-level, labeled **ADR/decision-violation** benchmark exists in Python (or any language); the nearest Python evaluations are SmellBench — 65 expert-validated architectural *smells* (not decisions) in scikit-learn, with 63.1% expert-judged false positives [61] — and the OpenStack/Qt erosion-symptom review-comment labels, which are review-text (not code) ground truth [78][79]. ADR corpora are language-agnostic (921-repo metadata set [20]; 4,911-ADR generation set [21]; 980-ADR violation study [8]).
5. **Ranked shortlist (most defensible first):** (1) decision-constrained bug localization; (2) violation-linked bug fixing with an attribution case study; (3) review-time decision conformance in diffs; (4) persistent-memory re-introduction guard (Shepherd-unique); (5) decision-guided migration/library upgrades; (6, adjacent) API-constraint enforcement ported to Python. Onboarding and test-generation-from-decisions have no verified published support — deprioritize (research notes T1 [96]).

**Gap (explicit):** no study found that shows architecture-violation detection reduces future defect rates via controlled experiment. ### (b) Per-task evidence

- **Bug localization/fixing:** bug files should be fixed as architecturally-connected groups and root causes (cycles, inheritance problems) located, not just locations [1]. Localization tooling itself is IR/learning-based (BugLocator ICSE 2012 [51]; AmaLgam ICPC 2014 [52]; DependLoc APSEC 2020 [50]; dependency-structure comparison ICSE 2019 [49]) and uses text/history/structure — **architecture-decision-level localization not found (gap)** [49][50][51][52].
- **Code review:** Paixao et al. (TSE 2021, journal extension of ASE'17; open-access UCL copy read in the verification pass) — 7 Java systems, 18,400 reviews, 51,889 revisions, 103,778 extracted structural-architecture snapshots: developers discussed the architectural impact of their changes in only **31%** of reviews; architectural awareness was rare (~29%; 51% for refactorings); and the architectural quality of the patch **decreased in 33%** of cases where developers provided architectural feedback [53] (OA: https://discovery.ucl.ac.uk/10085741/1/08697147.pdf). This directly supports review-time decision-conformance framing. Violation symptoms are also identifiable from review text (ML classifiers, arXiv 2306.08616, abstract-level) [54].
- **Onboarding:** controlled study (N=65) found documentation format does NOT significantly affect newcomers' architecture understanding; prior source-code exposure dominates — negative evidence for doc-format-centric onboarding claims [55]. Interview study (N=17): explainees seek decision rationale, not just structure [56].
- **Migration:** Arcan-based architectural-smell analysis guided an industrial microservice migration (ECSA 2019) [57]; JabRef institutionalized conformance checking (SACC) after erosion pain, with code churn linked to violations (ECSA'17 Companion) [58].
- **Refactoring:** violations identify high-impact refactorings (CSMR 2007) [59]; 50-project study ties smells to architectural-refactoring opportunities (ICPC 2020) [60]; longitudinal N=1 measured paydown (ICSE-SEIP 2019) [6].
- **LLM-era:** a 2026 study evaluated an LLM multi-model pipeline (1 primary + 3 validator LLMs) for detecting ADR decision violations (980 ADRs, 109 repos): strong on explicit, code-inferable decisions; weak on implicit/deployment decisions [8]. SmellBench (arXiv 2605.07001) evaluates 11 LLM-agent configurations on repairing 65 expert-validated architectural code smells in Python scikit-learn: best agent resolves 47.7%; **63.1% of tool-detected smells were expert-judged false positives** (κ=0.94 best expert agreement); repair aggressiveness and net codebase quality are inversely related [61] — the false-positive rate directly motivates Shepherd's dismissal memory. SAKE (arXiv 2606.29520) benchmarks 11 LLMs on architectural knowledge with uneven reasoning [61][62].

## RQ4 — Credible case study attributing bug fixes to architectural-constraint memory

Methodological precedents (all verified in the research notes [96]):

- **Component ablation + cost-normalized baselines:** SWE-agent ablations drop resolved% by 1.7–7.7 points on SWE-bench Lite (the five named ACI components: 3.0–7.7); a plain-RAG baseline resolves 2.67–4.33% vs 18.00% for the full agent on Lite (1.31% on full SWE-bench) at 8–13× higher cost-efficiency gap — flat retrieval is both weaker and cheaper, so arms must be cost-matched [80]. AutoCodeRover ablates SBFL hints (19%→22% resolved, $0.43→$0.47/task) [82]. Agentless ($0.70/task) shows manual ground-truth filtering (Lite-S) [81].
- **Perturbation / negative controls for retrieval:** CodeRAG-Bench (NAACL-Findings'25) shows retrieval saturates and can hurt (GPT-4o DS-1000 52.7→51.2 with gold docs); distractors degrade generation [69]. eRAG (SIGIR'24) shows relevance labels correlate poorly with downstream RAG performance — motivating per-document/memory-content perturbation [83].
- **Contamination controls:** SpecRover's data-memorization check [64]; LiveCodeBench's post-cutoff task windows [84].
- **Ground truth from history and mutation:** Maffort et al. mine architectural violations from version history (ESE 2015) [87]; specification mutation (Budd & Gopal 1985 [88]; Black et al. ASE 2000 [89]) creates labeled spec mutants. **No precedent for injected-violation ground truth in architecture conformance** (explicitly absent after search — the injected-violation control is an INFERENCE, the study's novel methodological element) (research notes T4 §0 [96]).
- **Python static baselines:** import-linter layer contracts (incl. indirect-import violations) and pydeps module graphs are implementable dependency-rule checkers — but they carry no decision semantics (no dismissal/supersession) (INFERENCE, per T4) [90][91].
- **Metrics:** localization@k (Xuan & Monperrus ICSME'14 [93]), resolved-rate pass@k, violation F1 with manual adjudication, cost USD/task [93][82][64].

### Proposed Shepherd case-study skeleton (design choices marked INFERENCE are extrapolations grounded in the precedents above)

- **Cases:** 2–3 mature Python repos with ADRs (multi-case replication logic per Runeson & Höst [85][86]); embedded units = bug-fix tasks mined SWE-bench-style [9].
- **RQs:** RQ1 efficacy (full system vs baselines on violation-linked bug tasks); RQ2 attribution (gains from persistent decision memory?); RQ3 persistence (re-introduction suppression across commits).
- **Baselines:** B1 BM25/dense RAG over repo+ADR text (with gold-doc oracle arm per CodeRAG-Bench [69]); B2 LLM-only; B3 import-linter/pydeps static checkers [90][91]. All cost-matched [80].
- **Ablations:** M0 memory removed (traversal kept, dismissals/supersessions wiped); T0 traversal removed (memory as flat RAG documents); S1 ADRs shuffled/replaced (negative control).
- **Controls:** C1 ADR mutation → labeled violation mutants (spec-mutation precedent [88][89]); C2 dismissed-violation re-introduction probes (replay diffs; measure re-alert suppression) — INFERENCE, no direct precedent; C3 synthetic violation injection (INFERENCE); C4 history-mined real violations + Agentless-style manual labeling [87][81].
- **Metrics:** localization@k, resolved rate pass@1/@3, violation F1, re-introduction rate (INFERENCE), cost/task.
- **Attribution decision rule:** attribute to memory only if (1) Δ(full−M0)>0 on violation-linked tasks; (2) Δ(full−S1) large (perturbed ADRs destroy the benefit → not generic text retrieval); (3) Δ(full−T0)>0 (flat retrieval underperforms traversal); (4) B3≈0 on dismissal/supersession-only cases (INFERENCE); (5) full suppresses re-alerts on C2 probes while M0 does not. If (2) fails, gains must be reported as retrieval-driven [69][83].
- **Threats:** contamination/memorization (memorization probe [64] + time-windowed tasks [84]); annotator bias (double annotation + adjudication; manual-classification precedent [81][82]); cherry-picking (full-set evaluation and all-cases reporting [9][81]; pre-registration of case selection recommended — INFERENCE); cost confound (cost-matched arms [80]); LLM stochasticity (pass@k variance [80]); single-repo overreach (multi-case [85][86]).

## Evidence-backed caveats and disagreements

1. **Correlation ≠ causation.** Every violation↔defect result is correlational or predictive; the only causal-flavored data is a single-repo longitudinal paydown [6]. Do not claim conformance checking reduces defect rates.
2. **Java dominates the evidence.** DRSpace [1][2][97], anti-pattern [3], Arcan [63], ArDoCo [28], API-misuse [22]–[27] lines are Java (or C/C++); Python-specific coverage is UNVERIFIED throughout — Shepherd's Python focus is a differentiator but also means evidence must be re-established. SmellBench is the notable Python exception, at smell level [61].
3. **Technical debt ≠ defects uniformly.** Zazworka et al. found only a subset of TD correlates with defect-proneness [47]; Martini's industrial work ties ATD to effort, not defect counts [45]. A Shepherd paper must not overclaim.
4. **Retrieval baselines are cheap but weak — and can hurt.** SWE-agent's plain-RAG baseline (2.67–4.33% on Lite; 1.31% on full SWE-bench) vs structured agent context (18.00% on Lite) supports Shepherd's structural-knowledge framing [80]; CodeRAG-Bench shows retrieval saturates/hurts, so ablation S1 is the decisive control [69].
5. **No released, code-level, labeled ADR/decision-violation benchmark exists in Python or any language**; the case study must construct its own labeled set (history-mined [87] + injected), which is both a contribution and a validity risk. SmellBench (Python smells, expert-validated) and the OpenStack/Qt review-symptom labels are the nearest prior work, at smell and review-text levels respectively [61][78][79].
6. **Unverified residues carried forward:** TSE 2019 anti-pattern subject languages [3]; Bench4BL Java label inferred [72]; Li et al. erosion-dataset download URL [78][79]; Archie DOI [95]; ArchBench read as abstract only [94]. (Paixao residue retired — see §Revision notes.)
