## Drill-downs (post-hoc, recorded for interpretation)

- **tuf class-bucket shift is attribution, not matching.** Same three exact-match rows in both arms; ADR-0001's `python2.7`/`python3.5` objects sit in class A under node_on and B/C under node_off. Trace check (run 1): under node_on the agent called `node_search("python2.7")`/`node_search("python3.5")`, got empty results (correctly-absent interpreter names), kept the bare objects — provenance records the object side as uncovered because the tool returned nothing. Under node_off it called only `search_code("tuf")`, whose hits covered the subject side. The `cls_A_matched`/`cls_BC_matched` effects on tuf are this tool-substitution reattribution on identical tallies.
- **experimenter node_off instability.** Runs 1/2 invented `ADR-0003 prohibits experimenter.experimenter.* -> django.db`, a broad prohibits on a core external dep firing 4167/4169 times (structural: fires on empty diff too); run 3 did not (~25 structural fires). No node_on run invented it. Registered routing treats structural fires as mechanism either way, but the arm asymmetry (2/3 node_off vs 0/3 node_on) is recorded as an observation.
- **tuf structural fire shapes.** node_on: `ADR-0004 prohibits tuf.* -> securesystemslib.formats` (28/cell) + `ADR-0006 prohibits tuf.api.metadata.* -> tuf.api.serialization.*` (13); node_off: `ADR-0004 prohibits tuf.api._payload.* -> securesystemslib` (12). Gold ADR-0004 emits zero edges, so all are resolver inventions; both arms invent, differently shaped.
- **Merge-mechanism family.** node_on carries more requires-with-wildcard-subject fires (tuf +4, flowkit +6.7, experimenter +88 beyond floor, 3/3) — the registered mechanism family (resolver over-extraction + merge fabrication), not arm movement.

## Decision (rules fixed pre-run)

**node_search: KEEP.** Gold-matching load moved beyond floor on flowkit (anchor-bait row, 3/3 consistent). The FP mass node_on adds (flowkit class-A decoy hedges, merge-mech family everywhere) is prompt-work residue per the pre-registered prediction and routes to **#146** (prompt/validation), not tool iteration. Detection-side expected units show **no movement in any repo** under either arm: the retrieval channel on this gold is insensitive to the tool surface at k=3, so retrieval-quality complaints are not tool-surface questions either.

## Caveats

- **Class-A provenance artifact:** the registered split cannot distinguish "object verified absent via node_search (empty result)" from "object never consulted" — both land in A. Refinement (e.g. recording consulted-but-empty node_search calls as tool-verified) routes to **#148**'s M1 instrumentation; not edited mid-batch per protocol.
- **Traces are local-only** (`logs/` gitignored, #140 convention): `logs/benchmark-arms-149/<repo>-<arm>-run<k>/resolver_traces.jsonl`, 282 records, preserved for #148 re-scoring.
- Smoke artifact (`benchmark/reports/smoke-2026-09-15/`, harness-validation cell) is not part of the batch denominator.
